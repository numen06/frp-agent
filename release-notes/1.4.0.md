# v1.4.0

日期：2026-11-06

- 主机资源按「组 → 主机 → 连接服务」组织。主机可加入已有 FRP 分组，同一台设备可独立添加 SSH、VNC、RDP、Docker 连接，各自设置地址、端口、凭据、授权及审计。
- VNC 默认直接配置 VNC 地址、端口和专用密码，不再要求先添加另一台 SSH 主机。SSH 隧道收为可选项，启用后分别展示 SSH 和 VNC 端口，继续严格核验 SSH 指纹。
- 传统 VNC 不提供传输加密，直连仅允许可信内网、VPN、FRP 内部/回环地址；拒绝公网与链路本地目标。连接域名时核验所有解析结果并拨号数值 IP，防止 DNS 重绑定。浏览器仍强制同源 HTTPS/WSS，拒绝无密码 VNC 服务。
- 增加主机身份表及连接归属迁移，保留原连接 ID、名称、凭据、授权、审计和已有 SSH 隧道配置。旧连接先分别对应主机，管理员可明确调整服务归属；不会依据同组、同地址或命名猜测并合并设备。
- 设备分组和归属不会扩大服务权限。只获 VNC 授权的用户看不到同机 SSH。原生 SSH/RDP 网关继续使用原连接名称；删除空主机受保护，删除分组时设备与连接保留并转为未分组。
- 运行维护区分 VNC 直连和 SSH 隧道；新增主机页面具有读取失败重试、未保存离页保护与手机布局。
- 后端、前端、Docker、Compose 统一版本 1.4.0，镜像使用纯版本号，验证后更新 latest。

升级前备份数据库、数据目录及部署配置并保留 `SSH_CREDENTIAL_SECRET`。主服务先完成迁移，再启动相同镜像版本的 WebSocket worker。迁移是增量的，回退旧应用时保留新增表和列，不删除历史授权或审计。

验收：219 项后端测试通过、4 项按环境跳过；桌面、390px / 320px 的真实 HTTPS 浏览器流程验证同一主机先添加 VNC、再添加 SSH、独立端口、可选隧道及仅授权服务可见。生产前端构建、VNC、Web SSH、RDP 预检、运行维护与主要侧栏导航回归通过。目标为协议测试夹具，未修改线上真实主机、凭据或授权。
