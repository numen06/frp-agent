# VNC / macOS 连接服务

从「主机资源」的连接列表添加或查找连接，可按所属主机和分组筛选。一台 Mac 可以同时配置 SSH 和 VNC，端口、凭据、授权和连接记录分别保存。VNC 直连不依赖 SSH，SSH 隧道是可选传输方式。

## 添加 VNC

1. 在 Mac 开启「屏幕共享」，允许 VNC 显示器使用专用密码控制屏幕。支持传统 VNC 密码认证，不支持仅 Apple ARD 账号认证。密码必须为 1–8 位 ASCII，平台拒绝超长密码，避免协议静默截断。
2. 在「主机资源」点击「添加连接服务」，选择 VNC。可以选择已有主机，留空时保存会同时创建同名主机。
3. 填写平台服务器可达的 **VNC 地址和 VNC 端口**，选择专用 VNC 密码凭据，用户名可填写 `vnc`，仅作标识。保存后为需要的用户授权该 VNC 服务。
4. 在连接列表打开「远程桌面」，使用平台 HTTPS 地址并点击「连接桌面」。浏览器不会获得目标密码。

手机端先点远程画面的密码框，再点「点此打开手机键盘」。输入 Mac 的锁屏密码后点「发送并回车」。输入框会清空，文字通过当前 VNC 会话作为按键发送。

直连只填写 VNC 服务本身的信息，无需添加 SSH 服务或填写 SSH 指纹。传统 VNC 直连不加密，平台仅允许回环、RFC1918 内网、VPN 的 CGNAT / IPv6 ULA 地址；拒绝公网、链路本地及元数据地址。域名在建立连接时校验所有解析结果，再连接已核验的数值 IP，避免 DNS 重绑定。网络管理者仍需确保所选网络可信，防火墙限制来源。

通过 FRP 接入时，使用平台可达的内部/回环入口及实际映射端口。例如平台 `127.0.0.1:15900` 转发到 Mac 的 `127.0.0.1:5900`，VNC 连接就填平台的 `127.0.0.1:15900`。不要把未加密 VNC 直接暴露到公网。

## 使用 Mac 自带的屏幕共享

1. 在 VNC 连接的详情中点「复制网关连接命令」，粘贴到本机 Mac 的终端运行。首次连接时，核对页面显示的网关指纹。
2. 用平台账号密码或已登记的 SSH 公钥登录。平台确认该账号有此 VNC 的连接权限后，终端会显示临时验证码。保持终端开启。
3. 点「复制 Mac 屏幕共享地址」。在访达按 `⌘K`，粘贴 `vnc://127.0.0.1:15900`。系统弹出密码框时，输入终端中的临时验证码。结束后在终端按 `Ctrl+C`。

屏幕共享地址指向本机，桌面流量由 SSH 加密转发到平台。平台使用保存的 VNC 凭据连接目标 Mac。此入口需要启用平台的 SSH 网关，VNC 连接本身可以独立添加。

## 可选 SSH 隧道

需要 SSH 加密传输时，在同一台主机下独立配置 SSH 连接服务，填写其地址、SSH 端口、密码或私钥，并检测、核验 SSH 主机指纹。然后在 VNC 连接中勾选「使用 SSH 隧道（可选）」，选择该 SSH 连接。表单分别显示 SSH 地址 / 端口和 VNC 端口；首次 SSH 指纹可在当前表单检测并记录，已有指纹不匹配不会自动覆盖。

SSH 隧道中的 VNC 地址固定为 Mac 的 `127.0.0.1`，VNC 端口通常为 `5900`；SSH 端口通常为 `22`，若经过 FRP 则填写实际 SSH 映射入口。两种协议不是一个端口。此模式只需向平台开放受保护的 SSH 入口，不需要再转发 VNC。Mac 需开启「远程登录」并允许 `direct-tcpip` 到本机 VNC 端口，可用 `PermitOpen 127.0.0.1:5900` 限制目的地。

## 保护与部署

- 浏览器到平台强制同源 HTTPS/WSS，平台先检查登录身份及该 VNC 服务的 `connect` 授权，再建立目标连接。禁止在 WebSocket URL 携带认证参数。
- SSH 与 VNC 凭据独立，使用现有 AES-GCM 加密保存。VNC 挑战认证在服务器完成，拒绝目标无密码认证，不向浏览器返回目标密码或挑战响应。
- SSH 隧道必须核验固定指纹，转发目的地固定为回环地址；直连检查可信目标地址。客户端不能自行指定目标。仅管理员可创建或修改连接配置。
- 浏览器 VNC 每个工作进程最多 16 个活动会话、每个账号最多 2 个、最多 32 个待认证连接。原生 VNC 网关每个进程最多处理 16 个 VNC 转发通道，每条 SSH 连接同时只允许一个桌面会话，输错 3 次后验证码失效。会话最长 1 小时。
- 每 5 秒复核账号、授权有效期、连接配置及凭据变化，撤销后自动断开。客户端 RFB 自动轮询会刷新空闲计时；最长 1 小时仍强制结束。
- 审计记录成功连接、结束、失败、时长和流量，不记录桌面内容、键盘输入或密码。连接测试不代表用户已经看到桌面。
- 分组或主机归属不会自动授予同机其他连接的权限。只授权 VNC 的用户看不到未授权的 SSH 服务，也无需取得 SSH 执行授权来使用可选隧道。
- 生产环境设置独立、稳定的 `SSH_CREDENTIAL_SECRET`。主服务和独立 WebSocket worker 应部署同一版本，沿用单 worker 的并发边界。

TLS 在反向代理终止时，转发 WebSocket Upgrade、原始 Host（含非标准端口）及可信 `X-Forwarded-Proto: https`。Uvicorn 只信任受控代理 IP，例如 `--proxy-headers --forwarded-allow-ips=<代理IP>`。

独立 WebSocket worker 可通过 `FRP_LOCAL_ADDRESS` 指定内置 FRP 节点的私网地址。已匹配在线内置 FRP 代理的 VNC 回环目标会使用该地址拨号，仍执行 VNC 直连地址校验。

## 旧数据兼容

升级自动补充主机身份和连接归属，保留连接 ID、名称、凭据、授权、审计及原 SSH 隧道配置。每条旧连接先对应一台主机，避免凭同组、同 IP 或名称猜测设备身份。确认属于同一设备后，编辑连接的「所属主机」将服务移动到同一主机；原连接名称继续用于原生网关登录。没有连接服务的旧主机可单独删除。

## 运行维护

管理员进入「运行维护 → VNC 防护」，查看服务配置、连接方式、上次手动检查和近 24 小时会话、异常及流量。配置检查不会尝试密码。流量来自共享审计数据库，只统计已结束会话，不表示当前在线人数；兼容独立 WebSocket worker。

## 隔离容器验收

可使用 `backend/scripts/check_vnc_live.py` 验证完整链路。它启动临时 HTTPS 应用、平台 SSH 网关和受密码保护的 RFB 测试服务，验证浏览器和原生 VNC 桌面帧、越权拦截、授权撤销、密码与指纹错误拦截及审计脱敏。

在 NUC 的测试镜像上运行（以下口令仅用于无网络、无数据卷的临时测试）：

```sh
docker -H tcp://192.168.8.119:2375 run --rm --network none \
  --memory 512m --cpus 1 --pids-limit 128 \
  -e VNC_DISPOSABLE_TEST=1 -e DATABASE_URL=sqlite:////tmp/vnc-live.db \
  -e AUTH_USERNAME=vnc-test-admin -e AUTH_PASSWORD=isolated-test-only \
  -e SSH_CREDENTIAL_SECRET=isolated-test-key-only \
  -e SSH_GATEWAY_ENABLED=false -e DOCKER_GATEWAY_ENABLED=false -e RDP_GATEWAY_ENABLED=false \
  -e PYTHONPATH=/app/backend --entrypoint python \
  registry.cn-shanghai.aliyuncs.com/numen/frp-agent:1.4.6 /app/backend/scripts/check_vnc_live.py
```

该命令不挂载宿主数据、不发布端口，全部服务在容器回环地址通信；不要将测试数据库指向真实部署。
